# ربط خدمة صالوناتي بمركز الأرجوان

هذه طبقة إضافية حول API الحالي. ملف worker.mjs والواجهات والألوان وقاعدة بيانات العملاء لا تتغير. البداية من فرع fix/security-deletion-audit-20261103، وليست main التجريبية.

نقطة الدخول الجديدة: workers/salonati-api/control-wrapper.mjs. يجب نشرها كوحدة متعددة الملفات مع worker.mjs وworkers/control-center/control.mjs، مع إبقاء bindings والأسرار ومسارات الخدمة الحالية. لا تُنشر على خدمة أخرى أو بقاعدة فارغة. نشر التطبيق يبقى خطوة منفصلة عن تجهيز هذا الفرع.

أنشئ معرف UUID واحداً لتركيب خدمة API عبر إعداداتها، واحفظه في ARJWAN_CONTROL_DEVICE_ID. هذه هوية تركيب للخادم، وليست بصمة جهاز لعميل. في المركز اختر المشروع صالوناتي والصيغة 3، ثم أصدر ملف الربط الموقع. خزّن الملف كاملاً كسر ARJWAN_CONTROL_ENROLLMENT في إعدادات الخدمة. لا يُحفظ الملف الموقع في git. الحسابات الفردية تظل تخضع لمصادقتها وموافقاتها الأصلية؛ قرار إيقاف هذا الربط يخص تركيب API ككل.

غياب الملف مع عدم ضبط ARJWAN_CONTROL_REQUIRED=1 يبقي السلوك الحالي. عند التفعيل تُفحص الكتابات، وتبقى GET وتسجيل الدخول والتصدير متاحة. التحقق الموقع قد يُحفظ في Cache API؛ إخلاء الذاكرة المخبأة قد يتطلب اتصالاً جديداً. انقطاع البوابة لا يمدد المهلة المحفوظة. لا توجد أوامر لمسح بيانات العملاء.

التشخيص مغلق؛ ARJWAN_DIAGNOSTICS=1 يسمح بإرسال ServerError والإصدار والنظام فقط عند استجابة 500 أو استثناء غير معالج، دون جسم الطلب أو الرد أو المسار أو العميل أو الحجز أو المبلغ. تقارير التكرار محدودة من البوابة.

الاختبارات: node --test workers/control-center/control.test.mjs، ثم deployment/test-control-runtime.mjs مع Miniflare. الأخير يعيد اختبارات API الأصلية عبر الطبقة الجديدة دون أي ربط خارجي أو بيانات حقيقية.
